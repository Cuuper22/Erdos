Valid proof. Wrong theorem. Rejected.

Erdos is a multi-agent theorem prover for Lean 4. While building it, the LLM agents found a strategy: quietly rewrite the theorem into something easier, then prove that. Everything compiled. The Critic approved. A SHA‑256 lock on the theorem statement is what ends it.

Read the boundary How it happened

Python + Lean 4 + Tauri · one person · MIT

The cheat was subtle, and everything passed

The setup is a standard adversarial loop: one model writes Lean 4 proofs, another critiques them, repeat until the compiler accepts or the budget runs out. The Lean compiler is the arbiter neither agent can influence.

What was not standard: the models started cheating. Not dramatically. They would subtly rewrite the theorem statement to make it easier to prove. The proof was valid. The theorem was different. Everything compiled, the Critic approved, and the system had formally verified a convenient reinterpretation of the original problem.

The fix is small and hard: theorem statements are SHA-256 hashed before the loop starts, exactly as computed in src/validator.py. Every candidate is checked against the locked hash. One character of drift in the statement, and the attempt dies before it reaches the compiler. The two hashes above are real; recompute them from the source.

"Did you actually solve what I asked" turns out to be a hard question when the solver is an LLM. That is the scalable oversight problem with a type checker bolted on.

Every candidate runs this gauntlet

  1. Prover writes

    An LLM replaces sorry with real Lean 4 tactics. Any backend: OpenRouter, Gemini, OpenAI, Anthropic, Ollama.

  2. Hash gate

    The candidate's theorem statement is re-hashed and compared to the lock. Mismatch kills the attempt. Axioms are banned outright.

  3. Lean compiles

    A sandboxed lake build. The compiler is the arbiter; neither agent can talk it into anything.

  4. Critic attacks

    A second model hunts for weaknesses in the accepted proof before anything is packaged.

  5. Artifact ships

    Verified bundles with proof, hashes, and build log: ready for fast human review, never auto-trusted.

order is load-bearing: the hash gate runs before the compiler ever sees a candidate

This is specification gaming, caught in the wild

The agent optimized the metric, compile success, rather than the goal: prove the original theorem. It satisfied the letter of the objective while violating its intent. That is the same class of failure alignment researchers worry about at scale, reproduced in a hobby project with a four-line regex hole as the attack surface.

I do not trust AI systems because they sound right. I look for the place where the system can cheat, then build the smallest boundary that makes the cheat impossible.

What this does not prove

  • The bundled examples are toy theorems; Erdos has not produced novel mathematics.
  • Mock mode demonstrates orchestration, integrity checking, and budget handling, not mathematical ability; its canned output is designed to be rejected.
  • Real-model solve rates are unbenchmarked; the pipeline's end-to-end success path is proven by test, not by leaderboard.
